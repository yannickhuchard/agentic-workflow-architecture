# AWA visualisation tools

| File | What it shows |
|---|---|
| `replay.html` | One run, replayed from its execution journal: animated tokens, node states, a timeline you can scrub, and the reasoning behind each step |
| `journey.html` | Several journeys and the customers in them: an atlas, one journey on calendar time, one customer's journey as a blueprint with mood, touchpoints, technology and what changed hands, and the run behind any part of it |
| `index.html` | A workflow definition, in 2D or 3D |
| `live.html` | A running workflow, by polling a local demo server |

## Replay

`replay.html` is a single file with no dependencies. Open it in a browser and either pick a sample run or drop two files on the page: the workflow definition (`.awa.json`) and the journal of one of its runs (`.journal.jsonl`).

To produce a journal:

```bash
awa run workflow.awa.json --journal run.journal.jsonl
```

It also loads from URLs, and can follow a run live from an AWA server over Server-Sent Events:

```
replay.html?workflow=<url>&journal=<url>
replay.html?run=http://localhost:3000/api/v1/workflows/runs/<run id>
```

| Control | Action |
|---|---|
| Space | Play or pause |
| ← → | Step back or forward one journal event |
| Home, End | Go to the start or the end |
| Click a node | See its contract, its attempts and what happened there |
| Drag, scroll, double-click | Pan, zoom, fit |

The picture at any position is computed from the journal events up to that position and nothing else, so what you see is exactly what was recorded. Marks above the timeline show failures (red), tool calls (green), actor reasoning (blue) and engine decisions (amber). A tool call's step shows what it ran, as a link, with its arguments, result, status and time.

`replay-sample.js` holds the sample runs. It is generated by `examples/claims-settlement/make-runs.mjs`.

## Journeys

`journey.html` needs no build step and no network. Open it in a browser: it shows the sample (`journey-story.js`, six customers through three journeys).

To see your own journeys:

| How | What |
|---|---|
| "Open a record", or drop a file on the page | The file written by `awa journey export`, or by `GET /api/v1/journeys/portfolio` |
| `journey.html?data=<url>` | The same, from an address |
| `journey.html?live=http://localhost:3000` | Follows an AWA server: the view updates as journeys progress, and a reader at the latest moment stays there |

`journey-story-builder.js` turns a record into what the view plays. It works on any record; an example may pass it hand-made workflow layouts and sentences for its own events, as `examples/claims-journey/make-story.mjs` does. `journey.check.mjs` checks the view in a browser (needs Playwright).

| Height | Shows | Go down by | 
|---|---|---|
| Journeys | Each journey with its stages and outcomes, how many customers go on to the next, and each customer's path and mood across them | Selecting a journey, or a customer's cell |
| One journey | Every customer in it on calendar time, with live counts per stage | Selecting a lane |
| One customer's journey | Mood, touchpoints, the journey's stages, the workflows behind them, the technology used and the documents exchanged, against the same moments | Selecting a workflow bar |
| One run | The workflow replayed step by step, with the journal evidence for each step | |

The switch at the top right moves sideways to another journey; on one customer's journey it keeps the customer. The arrows beside a customer's name move to the next customer in the same journey.

| Control | Action |
|---|---|
| Play, or the buttons beside it | Tell the story, step, or return to the start |
| ← → | Step back or forward |
| Esc | Go up one height |
| The address | Carries the place: copy it to share exactly what you are looking at |

On one customer's journey nothing is hidden: selecting a mark reads that moment and dims what comes after. "Read as a list" gives the same story as a dated list, by default only the customer's side.

A filled dot and a solid stretch of the mood line are something the customer said. A hollow dot and a dashed stretch are an inference by a rule of the journey; the caption gives the rule's reason.
