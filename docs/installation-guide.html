Installation

What you need, how to build, and how to check that your installation behaves as the specification says.

TypeScript SDK and the command line

Node.js 20 or later.

git clone https://github.com/yannickhuchard/agentic-workflow-architecture.git
cd agentic-workflow-architecture/sdk/typescript
npm install
npm run build

The command line is then node dist/cli/index.js, or awa after npm link.

The package name on npm is agentic-workflow-architecture. Check which version is published before relying on it: what this guide describes is SDK 2.0.0.

CommandWhat it does
awa runRun a workflow file; keep its journal and checkpoints
awa journeyJourneys kept in a runtime directory, or with --store in a PostgreSQL store several hosts share: add definitions, take in events, let time pass, list, show, export
awa measuresThe measures of journeys and workflows, computed from what was recorded
awa replayCounterfactual replay of a recorded run
awa recipeCompile a workflow and a journal into a build-from-scratch recipe
awa knowledgeDistil, review and exchange knowledge from journals
awa serveThe HTTP interface
awa taskHuman tasks: list, assign, complete
awa init, awa generateStart a project; draft a workflow from a description

Python SDK

Python 3.10 or later.

cd sdk/python
pip install -e '.[dev,web]'
pytest -q

The Python SDK passes every conformance level, as the reference does: the engine rules, tools, model routing and model decisions, journeys, measures, replay, contexts and service levels. Install it with pip install agentic-workflow-architecture; the package you import is awa. Its built-in AI agent calls no model: supply your own actor, or an OpenAI-compatible provider. It has no recipe and no Open Knowledge Format exchange.

Model providers

Activities name a capability tier (tier:fast, tier:balanced, tier:reasoning), not a vendor. A deployment maps each tier to providers in order of preference; when one fails the next is tried.

ProviderNeeds
googleGEMINI_API_KEY
openaiOPENAI_API_KEY
ollamaA running Ollama; OLLAMA_BASE_URL if not on localhost
embeddednpm install @huggingface/transformers. A small open-source model in-process: no server, no key
awa run workflow.awa.json --providers google,ollama,embedded --journal run.journal.jsonl

Small embedded models follow a reply format well and judge poorly. Measurements are in embedded-models.md.

The HTTP interface

AWA_DATA_DIR=./.awa awa serve --port 3000 --api-key mykey:admin
VariableEffect
AWA_DATA_DIRJourneys, their runs and journals are kept in this directory and survive a restart. Without it they live in the process
AWA_RUNTIME_STOREA PostgreSQL URL: journeys, runs and journals are kept in that database, and several servers may share it (also --store). Not to be confused with AWA_DATABASE_URL, the database of tasks for people
AWA_WORKFLOWS_DIRThe only directory from which POST /workflows/run will run a file
AWA_SIMULATE=1, AWA_SIMULATED_OUTPUTSRun activities without calling models or tools
JWT_SECRETAccept signed tokens as well as API keys

The interface is described in spec/openapi/awa-api.yaml.

Check conformance

The conformance suite is what "implements AWA" means. Run it against either SDK:

cd sdk/typescript && npx vitest run tests/conformance.test.ts
cd sdk/python && pytest tests/test_conformance.py -rs

Cases at levels an SDK does not claim are reported as skipped, never hidden.

The normative text is the specification. Where this guide and the specification disagree, the specification is right.
