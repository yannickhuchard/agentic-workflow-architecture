Specification 1.1 · SDK 2.0.0

Workflows where the outcome is fixed and the strategy is free

AWA is a specification for workflows carried out by AI agents, people, robots and applications together. An agent may reach a result by different means each time, so AWA fixes what must be true of the result, records how it was reached, and refuses results it cannot verify.

What AWA is

Three things, kept apart on purpose:

A specification

Version 1.1. Twenty sections saying what a workflow document means and what an engine must do with it. Written with MUST and MAY.

A conformance suite

Language-neutral cases: a workflow, scripted actors, the outcome an engine must produce. An implementation claims a level only if it passes every case at that level.

Reference implementations

TypeScript SDK 2.0.0 passes every level. The Python SDK passes the engine levels. Java has the data model only.

The specification and the SDKs are versioned separately: the specification says what a document means, an SDK version says what its API promises.

What it gives you

LayerIn one sentence
DocumentA workflow as JSON: activities, actors, roles, edges, decision tables, events.
FlowSequence, conditional routing, parallel split and join, timers, compensation, cancellation.
DecisionsDecision tables with a specified entry language and strict hit policies; a model may decide, within options the workflow lists.
Outcome contractsPer activity: output schema, postconditions, budgets, escalation to a person. Checked deterministically, failing closed.
ResilienceRetry with backoff, dead letters, checkpoints, recovery in another process, idempotency keys.
JournalAn append-only record of every run: what happened, the actor's reasoning, the engine's own decisions.
ToolsHTTP, command, JSON-RPC, gRPC, MCP and function calls, each journalled with a link to what ran.
Business eventsWorkflows publish events and wait for them, with correlation and a deadline that has its own path.
JourneysThe life of a customer across several workflows: stages, goals, touchpoints, what changes hands, and an estimate of mood that always says whether it was measured or inferred.
ExplanationA replay, a recipe that explains how to rebuild the workflow, and counterfactual replay: what would this run have done under another model or rule?
KnowledgeStrategies and failure patterns distilled from runs, reviewed by people, exported as an Open Knowledge Format bundle.

A first run

From a clone of the repository, with Node.js 20 or later:

cd sdk/typescript && npm install && npm run build

Run an example without any API key. --simulate replaces models and tools; --outputs says what each activity returns:

node sdk/typescript/dist/cli/index.js run examples/claims-settlement/claims-settlement.awa.json --simulate --outputs examples/claims-settlement/simulation.json --journal run.journal.jsonl

Then turn the journal into a document that explains how to build that workflow from scratch:

node sdk/typescript/dist/cli/index.js recipe examples/claims-settlement/claims-settlement.awa.json run.journal.jsonl -o RECIPE.md

To see a run, open the run replay. To see six customers through a year of journeys, open the journey view.
