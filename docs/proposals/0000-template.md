# AEP NNNN: Title

| Field | Value |
|---|---|
| Status | `draft` |
| Author | Name and GitHub account |
| Created | YYYY-MM-DD |

| Sections | The sections of `docs/specification.md` it adds or changes |
| Conformance level | The level whose cases it adds or changes |

## Problem

The situation the proposal addresses, who meets it, and what they do today.

## Proposal

The change in plain words: what a document can now express, and what an engine now does.

## Normative text

The text to add to the specification, written exactly as it will appear, with MUST, SHOULD and MAY.

## Schema changes

The properties added to or changed in `spec/json-schema`, with their types and defaults.

## Conformance cases

The cases that test the change: for each case, its identifier, its input and its expected outcome. Each rule of the normative text has at least one case.

## Effect on existing documents

How documents that are valid today behave after the change. A change that alters the meaning of a valid document is a major change and is listed in Appendix B.

## Alternatives considered

The other designs that were considered, and the reasons for the choice.

## Implementation notes

What the reference implementation and the Python SDK change, and any guidance for other implementers.

## Out of scope

What the proposal deliberately leaves to a later proposal.
