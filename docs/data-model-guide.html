Specification 1.1 · SDK 2.0.0

Data model

The things AWA names, what each is for, and where each is defined. The JSON Schemas in spec/json-schema are normative; OpenAPI, GraphQL, Avro and the PostgreSQL DDL are projections of them.

Workflow

ThingWhat it is
WorkflowActivities, edges, decision nodes, events and roles, with an awa_version
ActivityOne unit of work, performed by one kind of actor: human, ai_agent, robot or application
EdgeWhere a token may go next. With a condition it is a choice; several edges without one are a parallel split
Decision nodeA choice made by a decision table, an external rule engine, a model within listed options, or a table first and a model for what no rule covers
Eventstart, end, timer, and message or signal, which publish a business event or wait for one
RoleWho performs activities; for an AI role, which model, named by capability tier

What an activity can carry

PropertyPurpose
outcome_contractWhat must be true of the result: schema, postconditions, budgets, what to do on a violation
verificationAcceptance criteria judged by schema, by a model or by a custom check; fails closed
retryHow often and how patiently to try again
compensationThe activity that undoes this one if the run later fails or is cancelled
toolsThe tools the actor may call, each with a binding
knowledgeWhether reviewed knowledge from earlier runs is given to the actor
joinall to wait for every incoming branch

Run

ThingWhat it is
RunOne execution of a workflow. Status: running, waiting_human, waiting_event, completed, failed, cancelled
TokenA position in the run. A parallel split makes more; a join merges them
Journal eventOne entry in the run's append-only record. Schema: journal-event.schema.json
CheckpointThe state from which another process can continue the run

Journey

ThingWhat it is
Business eventA statement that something happened, in CloudEvents 1.0 form. Its type is the name workflows and journeys refer to
JourneyStages a subject passes through, the workflows that serve each, triggers, goals and exits
Journey instanceOne subject on one journey, with its record. Joined to its runs by run_id and to the subject's other journeys by the subject key
ArtefactA kind of thing that changes hands, as the business names it: contract, attestation, invoice, receipt, certificate. A business concept, not a file format
TouchpointA moment of contact: party, direction, channel, technology, and the artefacts exchanged. Realised by an event, an activity or a tool call
MoodAn estimate that changes only by declared rules. Every change is recorded as measured (the subject said so) or inferred (the authors assumed so)
"artefacts":   [{ "id": "insurance-contract", "name": "Insurance contract", "kind": "contract" }],
"touchpoints": [{ "id": "contract-signed", "name": "Signs the contract", "direction": "inbound", "channel": "web",
                  "technology": "E-signature service", "on": { "event": "contract.signed" },
                  "exchanges": [{ "artefact": "insurance-contract", "reference": "contract_id" }] }],
"sentiment":   { "rules": [{ "on": "waited", "longer_than": "P2D", "change": -1, "reason": "waited more than two days" },
                           { "on": "event", "event": "survey.answered", "measure": { "path": "satisfaction", "from": [1, 5] } }] }
