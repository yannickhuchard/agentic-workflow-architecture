| 2026-11-22 | 21:00 | **Journey view, touchpoints, exchanges and mood**. New `tools/visualization/journey.html`: an atlas of journeys, one journey on calendar time, one customer's journey as a living blueprint (mood, touchpoints, stages, workflows, technology, documents exchanged) and the run behind any part of it, with a journey switch and customer arrows for moving sideways. Journeys now declare `artefacts` (business kinds: contract, attestation, invoice, receipt, certificate and others), `touchpoints` (party, direction, channel, technology, what is exchanged; realised by an event, an activity or a tool call) and `sentiment` rules; the record gains `journey.touchpoint` and `journey.sentiment_changed`, every mood change marked measured or inferred, and mood carries over to the subject's next journey (specification 19.7 to 19.9). `journey_transitions` reports movement between journeys. The host now takes in events that runs publish, as soon as the publishing run settles, and records an event only on journeys it concerns (19.5). Example extended to three journeys (purchase, claim, renewal) and five workflows; `persona-walkthrough.mjs` checks the view against each reader's question. | No |
| 2026-11-22 | 18:00 | **Business events, journeys and counterfactual replay** (specification sections 18 to 20). `message` and `signal` events now publish business events (CloudEvents 1.0) or hold a token until one arrives, with correlation, a deadline and a timeout edge; run status `waiting_event`; `deliverEvent`, `expireEvents`, `nextEventDeadline`; new conformance level `events` with 7 cases. `AwaRuntime` hosts many runs behind one event entry point. **Journeys**: stages, triggers, goals and exits over business events, each run linked by `run_id`, funnel analytics; JSON Schemas `journey.schema.json` and `journey-event.schema.json`. **Counterfactual replay**: `awa replay` re-runs a journal under a changed model, prompt, contract or rule with tools, people, applications, events and time held as recorded, and reports regressions (exit status 2). Runs can be withdrawn: `engine.cancel(reason)` cancels unfinished tokens, compensates and leaves the run `cancelled` (section 5.8); a journey that ends through an exit cancels its runs. Engine clock is injectable (`now`). Server: `POST /events`. New example `examples/claims-journey`. `message` and `signal` events used to fail with `UNSUPPORTED_EVENT`; documents that used them without `event_definition.name` are now rejected (`invalid_event`). | No |
| 2026-11-22 | 12:00 | **SDK v2.0.0 — AWA Specification 1.1**: AWA becomes a normative specification ([docs/specification.md](docs/specification.md)) with a reference implementation and a language-neutral conformance suite ([spec/conformance](spec/conformance)). **Correctness**: a run with a failed token is `failed`; routing never guesses an edge; verification fails closed; one specified condition expression language. **Execution journal** at three trace levels (execution, actor reasoning, engine decisions), JSON Lines interchange, live Server-Sent Events stream. **Resilience**: per-activity retry with backoff, dead letters, checkpoints, recovery in another process, idempotency keys. **Outcome contracts**: output schema, postconditions, budgets, escalation to a human. **Flow control**: parallel split and synchronising join, start/end/timer events, fail-fast cancellation, compensation. **Model routing**: capability tiers with ordered fallbacks; providers for OpenAI, Google, any OpenAI-compatible server, Ollama, and a small open-source model embedded in-process. **Decisions**: specified decision table entries and strict hit policies, chained decisions, model decisions within enumerated options, plug-in point for external rule engines. **Tools**: HTTP, command, JSON-RPC, gRPC, MCP and function bindings, every call journalled with a link to what ran. **Explanation**: `awa recipe` and the replay visualiser `tools/visualization/replay.html`. **Knowledge layer**: distilled from journals, compounding, review-gated, exported as an Open Knowledge Format v0.3 bundle (`awa knowledge`). New example `examples/claims-settlement`. Python SDK reaches the `core` and `decision` conformance levels. OpenAPI, GraphQL, Avro and PostgreSQL DDL brought up to 1.1. CI added. **Breaking**: runs that completed by luck now fail (a failed token fails the run; a choice with no true condition and no default edge fails with `NO_ROUTE`); several unconditional edges from one node are a parallel split; `unique` and `any` decision tables fail on conflicting rules; unverifiable outputs are rejected; the AI agent default temperature is 0.2 (was 0.7) and agents are asked to reply as `{reasoning, output}`; simulated activities return no business data, so data-dependent workflows need `--outputs`. | Yes |
